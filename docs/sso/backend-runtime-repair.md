# 登录后后端退出问题修复

日期：2026-10-13。

实际故障为：SSO 登录成功后，商品接口调用 `guancli` 读取 BI 卡片；当前 Windows 机器没有该工具，触发 `spawn guancli ENOENT`。原有多个 BI 客户端没有监听子进程的 `error` 事件，导致 Node 进程退出。之后商品页面和登录页均无法连接 3737。

修复了以下行为：

- 商品、交期、画像、尺码、成本、销量、剩余库存统一处理工具启动错误、退出失败、读取超时和输出过大。BI 请求失败不再结束后端进程。
- 卡片临时文件使用系统临时目录，成功或失败后清理，兼容 Windows。
- 销量读取失败时返回接口错误，不将失败结果保存为零销量缓存；正常销量的计算口径、BI 数据源 ID、筛选条件均保留。
- SSO 登录后的商品同步保留调用者的会话，避免后端内部重拉商品请求被登录门禁拦截。
- 登录页在连接恢复后清除旧的连接失败提示，并恢复登录入口。

验证包含原有 19 项 SSO 测试与新增 4 项运行环境测试。新增测试启动隔离副本中的真实 Express 后端，使用模拟 SSO / 领猫数据源及不存在的 BI 可执行文件，依次验证：登录、商品加载、画像与销量出错、后端持续响应、商品同步、退出、退出后业务访问被拒绝。测试不修改实际业务数据和客户端凭证。

真实环境中，原有领猫凭证成功读取 331 款商品，3737 的健康和登录会话接口恢复响应。本机仍缺少 `guancli` 和对应的 BI 登录配置；BI 库存、画像和销量数据尚未恢复。需提供工具安装位置或 BI 接入说明后继续配置，不能把领猫商品数量或接口恢复视作 BI 数据完整。

可使用进程环境变量 `GUANCLI_PATH` 指向已安装的 BI 可执行文件；也可将正确的工具加入后端进程的 `PATH`。当前未安装来源不明的替代工具，未改动原有 `server/.env`、依赖声明、锁文件或业务配置。

复现检查，在 `app` 目录使用 Node 22：

```powershell
node --test tests/sso-auth.test.mjs tests/backend-runtime.test.mjs
npm run build
```

服务运行后，在项目根目录执行 `node docs/sso/browser-check.mjs`。浏览器验收还包含连接中断后恢复登录入口的检查。真实账号登录仍由本人进行。
